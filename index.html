RoyaleTracker.gg

Analytics platform · in production since January 2026

Built with Angel Tonov (@MrFann1)

A statistics platform for Clash Royale. A data pipeline ingests match records from the game's official REST API around the clock, and the platform turns them into rankings, leaderboards and user profiles, served as server-rendered pages.

887K+records ingested per day
38M+records stored (45-day retention)
184detail pages ranked from live data
300+pages in the sitemap

Figures measured in October 2026.

  • Data pipeline. Replaced web scraping with our own ingestion. A long-running worker polls the API for a managed pool of users, deduplicates records that arrive from more than one source and classifies them before storing them in PostgreSQL. A nightly batch job rolls raw records into weekly aggregates that outlive the retention window, and an automated verifier recomputes every aggregate from the raw data.
  • Statistically sound rankings. Results are ranked by the Wilson score lower bound with a minimum sample size, so a small sample cannot outrank a large one, and anomaly filters remove manipulated data before it reaches the rankings.
  • Reliability. Each production incident became a permanent safeguard: create-before-revoke rotation for IP-bound API keys, cache bypass after upstream outages, an eviction job after a disk-full outage, request deadlines on slow queries, and a health monitor that reports to Discord.
  • LLM integration. Two features run on the Anthropic Claude API, a recommendation engine and an automated rater, with per-device and per-network rate limits stored in PostgreSQL.
  • Technical SEO in code. Structured data generated from the page's own values, a single canonical URL builder, dynamic Open Graph images and correct 404 / 410 responses, verified by an automated audit script.

BrawlMetrics.gg

Analytics platform · in production since July 2026

Built with Angel Tonov

A statistics platform for Brawl Stars with a separate pipeline built for higher volume: each record is aggregated into counters at ingest time and then discarded, which keeps storage small while processing more than 1.4 million records a day.

1.45M+records processed per day
93M+records aggregated since August 2026
16.7Muser profiles indexed
390+pages in the sitemap
  • Adaptive rate limiting. The ingestion worker runs at 30 requests per second, halves its rate on any HTTP 429 and recovers gradually, so it stays close to the API limit without being blocked.
  • Single-worker guarantee. A PostgreSQL advisory lock ensures only one ingestion worker runs at a time, a scheduled watchdog restarts it, and health checks alert when a day ingests no data.
  • Performance. Cut a failing endpoint from 16 to 18 seconds to about 1 second by removing repeated computation, fixing a cache stampede with single-flight request coalescing and adding memoisation with a tuned TTL.
  • Statistical guardrails. Results based on fewer than 300 samples (100 for pairwise comparisons) are returned as "insufficient data" instead of a misleading percentage.
